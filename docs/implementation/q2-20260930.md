## Portable native continuation packet

The policy packet above was independently reviewed and integrated as `05cbbc3`. The following separate packet implements `qa.native-q2-continuation` version 1, with an empty backend identity. Public capture, candidate-only restore, final reconnect and detached source descriptor APIs are in `include/qa/game_q2_checkpoint.h`.

Seven new C files under `src/gameplay/q2/save` encode each logical field, little-endian integers, exact finite floating values, tagged damage/armor/hand-action unions, counted string values and saved actor slots/generations. No C struct memory, process pointers, function addresses or live registry namespace is serialized. The codec covers classic and rerelease RNG state, actor traversal order, weapon/projectile/grapple/hand actions, item/companion/power state, players and collective client state, map/mover/turret/N64 state, authored monster moves/reinforcements and collective trails/alerts. Existing source checkpoint validators remain the semantic boundary. Arrays check encoded extents before allocation; unsupported versions, truncated fields, invalid actor order, duplicate actor slots and trailing bytes fail.

Private restore runs after the shared actor registry and before shared gameplay stores. It suppresses inventory action admission, power-cell binding, pickup observations and target publication. Hand grenade ammunition is captured as a value observation and compared with restored shared inventory at reconnect. Saved private inventory-definition and pickup-observation lease serials are adopted from the imported shared serial namespace. Target descriptors are compared with the restored registry through `qa_persistence_targets_binding`; reconnect preserves its saved binding serial. Q2 uses canonical primary combat/inventory stores and installs no shared scheduler callbacks: actor turns consume its restored private `due_ns` and think enums. The think resolver rejects invented scheduler identities.

Capture leaves its output unchanged on failure. Restore failure poisons its isolated candidate. Successful restore remains inactive until `qa_q2_game_restore_finish` validates/adopts all source bindings. No spawn, use, touch, damage or presentation callbacks replay. Source descriptor APIs borrow game-owned native item admissions and existing callbacks; they initialize no gameplay state and mutate no shared store.
