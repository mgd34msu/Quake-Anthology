# Native Q2 frontend continuation

This packet adds actual early constructor admission and late private GAME
frontend continuation. It does not claim complete CGAME or native Q3 module
continuation. Verification is source-only; no compiler, tests, parser or project
executable was invoked.

`frontend_native_q2_topology_checkpoint` captures every physical native lease,
including lazy GAME leases with no image/audio/font heaps. Each row records its
real foundation owner key, original import profile, audio identity, owned VFS
view, borrowed provider VFS view and installed heap flags. The enclosing captured
content graph supplies view identities. Keys decode by readonly lookup in the
restored foundation strings, before provider factories exist.

After `frontend_topology_prepare` has adopted the actual frontend clock/identity
counter and Q3 constructor groups, `frontend_native_q2_prepare_restored` validates
the complete native row shape, identities and views. Native identities cannot
duplicate real prepared or constructed Q3 identities. Native rows cannot repeat
an owner/profile, identity or owning view. The real mounts/provider views must
share their actual resource pool. Native preparation claims each saved owned
view once and creates its saved empty resource/audio/font heaps without loading
content. Rows are installed in saved physical order before any claim or heap
creation can fail, so a failed candidate retains every partial owner.

While the enclosing source constructor policy is active,
`frontend_native_q2_services` consumes the exact saved owner/profile row once.
It requires the actual incoming `engine.content_files` pointer to match that
row's borrowed restored provider view, then binds the real provider cvars,
context and idle callback. It does not clone another view, allocate another
lease or increment the saved audio identity counter. Ordinary live construction
retains its existing VFS clone, identity and lease creation behavior.

The aggregate's global image, font and audio families use
`frontend_native_q2_owner_count/owner_read` to enumerate actual heaps in physical
order. Those families must restore their genuine saved objects before the native
private section; this packet does not decode a second set of image/PCM/font
objects. `frontend_native_q2_topology_ready` rejects unconsumed rows and active or
mismatched real owners. After all private families qualify,
`frontend_native_q2_topology_finish` removes only native candidate classification,
then the enclosing source constructor policy may finish. Rebind readiness rejects
prepared or unfinished native rows.

The private GAME section captures the real lease frame clocks, seat/viewport
state, alternate flag, actual local classic-font ordinal and retained world
text. It validates that the classic pointer belongs to that actual font library;
decode requires the restored ordinal to describe the source-created classic
`native-q2:conchars` font. All row identity/heap/font qualifiers pass before any
private row writes. A later failed world-text import retains the isolated
candidate for discard; it never publishes partial state.

The actual GAME import filter in `application_import_body` admits KEX debug
text slots 59/60, so GAME can retain world text. The real world draw path can
then create images/fonts/classic. GAME sound imports independently create image
and audio heaps. The filter returns before the CGAME localization, picture and
return-string paths. `native_q2_game_private` therefore qualifies GAME's actual
localization pool count, picture list and all eight guest string slots as empty;
it does not infer empty state for another profile. CGAME private continuation
fails explicitly until its original module allocations/catalog producers are
qualified.

`qa_font_world_store_checkpoint/restore` serialize actual retained text bytes,
geometry, color, font/orientation, content identity, expiration and one-frame
observation state. Capture does not prune, snapshot, mark an entry observed,
draw or consult a clock. Restore prepares an independent row array and all text
buffers, resolves actual content owners, checks the original submission bounds
and exact wire extent, then replaces the store. Failed decoding leaves that
store unchanged. Native GAME content callbacks require every retained text row
to belong to the exact source owner. The new readonly localization pool query
neither loads nor trims catalogs.

Candidate teardown must retire genuine application/native leases first, then
call `frontend_native_q2_discard_unbound` before shared frontend stores close.
Bound leases are consumed only by the actual application's release callback.
The pending destructor rejects any surviving bound or active lease; it can then
release partial prepared claims without accessing the already-retired provider.
VFS views hold their own real resource-pool references through that cleanup.

Required outer consumer work remains explicit: the full frontend envelope must
carry both native sections, run early admission before provider construction,
restore global heap objects before late native state, require all native rows
bound and finish classification only after complete validation. Its destructor
must call the pending cleanup. These APIs do not declare that outer pipeline
complete. CGAME full module continuation, nonempty localization holders outside
the source-qualified GAME profile and unsupported native Q3 owners remain
separate genuine producer obligations.
