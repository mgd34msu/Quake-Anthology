# Native player bots: implementation record

This packet implements B26 native player decision execution. It is work in
progress. The source has not been compiled or run, under the current baseline
instruction. No runtime acceptance or feature completion is claimed.

## Ownership and production path

The application adapter in `src/app/application/bots.c` borrows the canonical
application session, world, combat, inventory, player roster, selected providers,
and mode service. It owns one bot library/runtime, private AI continuations,
per-client actor-bound navigation views, and shared graphs keyed by the selected
movement provider/profile/bounds. Map bytes are retained through the existing
resource owner. Personality scripts use an owned VFS view; source script resources
retain their own resource leases.

`qa_application_player_actor` supplies actual admitted player actors. No bot
actor allocator, competing inventory, collision world, or scheduler is added.
The population submits through `qa_application_control_move`, with typed Q1/Q2
weapon selection only when the requested weapon changes. The ordinary application
control path owns arsenal cadence and firing. Q3 source byte commands are retained;
foreign movement receives semantic direction/action conversion.

Root integration has inserted frame dispatch in application `owner.c`, actor
retirement in `services.c`, and map publication/destruction admission in
`publication.c`. Finalization closes bots in `lifetime.c` while shared gameplay
services still exist. The helper `application_bots_publish` constructs
the population after the ordinary player roster and selected movement are present.
`application_bots_can_destroy`, population readiness, and runtime readiness reject
teardown while callbacks or borrowed owners are active. Retired actors retain their
private navigation owners until population teardown.

## Native decision implementation

The AI source now includes combat target selection, canonical monster targets,
explicit independent-mode team checks, learned selected-arsenal choice, aggression,
retreat, aiming, firing admission, attack movement, nearby/long-term goals,
chasing, respawn/observer/intermission transitions, explicit point/follow orders,
and queued chat replies. Decisions have a bounded transition loop. A private
activation stack resolves native Q1 door/button/controller blockers, moves to
touch activators or aims and fires through ordinary actions at shootable targets.
Activation state is checkpointed with the other private decisions. Navigation,
goal, character, chat, action, and movement owners are shared existing C services.

The application mover adapter now projects both Q1 and Q2 typed source
observations into the existing navigation/model/activation interfaces. It selects
the actual canonical map actor owner, so movement-family selection does not hide
foreign source movers. Q2 elevator phase and endpoints, native train destination,
team offsets and unambiguous route prefixes come from `qa_q2_entity_mover_read`.
Both source adapters use the same retained train-stop buffer; a borrow guard
rejects callback reentry while source inspection writes it, and readiness/teardown
admission includes that guard. Q3 source mover projection remains unfinished.

The selected player adapter reads canonical body/combat and ordinary movement.
The selected arsenal adapter reads actual canonical weapon/ammunition item IDs;
it does not replace the inventory with Q3 slots. Scratch Q3 personality indices
exist only in detached observations/learned selection. Q3 weapon metadata comes
from the actual loaded bot library. Q1 now enumerates the native
`qa_q1_player_weapon_read` observer for every source weapon enum, including
Hipnotic, Rogue, MG3 and CTF weapons. It shares the live source's shape/timing
definitions instead of keeping another base-Q1 constants table. Native ownership,
availability, fallback, ammo cost, discharge, fire continuation, muzzle origins
and grapple travel come from detached source facts. Source callbacks execute
inside an arsenal scratch lease; reentry cannot replace that borrowed table,
and source retirement or a changed selected arsenal discards its observations.
Primary muzzle traces use source vectors relative to the canonical actor rather
than a foreign movement eye. Paired origins are retained; current AI safety
checks still use the primary muzzle. Launch delay contributes to projectile
target prediction; native gravity acceleration is retained for the pending
trajectory solver. These are nominal next-shot facts, not full future hammer,
homing or replacement-projectile predictions.

Q2 ballistics still derive from the TypeScript prototype's source-aware knowledge
adapter, with native C floats and retained observation storage.
Source-inspected Q2 BFG, disintegrator and chainfist observations
extend the prototype's admitted rows. Actual source weapon/ammunition indices,
learned personality roles, and weapon travel capabilities have separate meanings.
Native Q3 uses its exact learned roles; foreign roles project only scratch indices.
Selected Q1/Q2 rockets and Q3 rocket/BFG/grapple advertise typed travel capabilities;
travel admission checks actual weapon ownership and ammunition.
No source files were copied from `qsrc`.

Personality admission resolves a named installed bot script when available and
otherwise uses the installed default. Ordinary application cvars supply native
bot pause, interval, challenge, chat and travel controls. Existing registered
scalars retain their values. Q3 Team Arena admission follows the selected actual
arsenal product.

High-skill projectile aim can replay the target's selected native movement kernel
using a retained actor-bound navigation view over shared graphs and world services.
The target workspace rejects reentry and is reclaimed after actor retirement.
Radial aim checks the actual target ground and intervening collision. Source-specific
prediction phase/touch hooks still need the application's paired detached lease;
the current kernel projection does not claim those hooks. Guest movement targets
use the basic kinematic estimate until an actual guest prediction adapter exists.

Carried flags and harvested tokens come from the selected shared mode owner,
independent of the arsenal family. Tag chase uses the actual retained carrier;
a tag owner is not treated as a flag carrier. Submitted ordinary movement retains
fractional milliseconds instead of discarding time between commands.

Private bot checkpoints own decisions, actions, goals, movement continuation,
chat queues, and learned weight clones. Restore currently requires identical
actor/resource/character bindings. This is a same-binding checkpoint, not the
finished application save codec or a new-session roster reconstruction facility.
The canonical session RNG, actors, navigation, shared bot variables, and shared
chat cooldown owners remain separate checkpoint responsibilities.

## Actual pickup observations

The shared pickup registry has an actor-slot observer lookup, full actor generation
checks, exact serial retirement, deferred descriptor reclamation, and pure
synchronous source inspection. Results contain detached scalar offer identity,
availability, dropped status, and utility. Inspections cannot execute item grants.
Source providers must retain themselves for the complete callback.

`qa_pickups_preview` uses the same selected recipient rule admission as actual
pickup execution. A recipient replacement rule has a pure preview callback;
blocked or stale grants refuse. Native original policies perform their own preview.
Cargo preview shares the resolved grant preview kernel with singular supply offers.

Q1 source item and backpack observation callers were implemented by the Q1 owner.
Q3 ordinary item admission now registers observers. Its callback reads actual
hidden state, authored quantity, source ammo cap and weapon top-up rules, health,
armor, holdable and persistent restrictions. Objective pickups remain the explicit
selected-mode AI's responsibility; observation never invokes the mutating objective
hook. Q3 checkpoint restore prepares required observers before replacing actor
arrays, then commits observer ownership without a failing post-swap registration.
Public rebinding supports the session reconstruction caller still being integrated.

The application goal adapter enumerates canonical actors in source order, inspects
registered source items, and passes utility to the existing goal chooser. It skips
inferred classname-based native item weights. The current checkout has no production
recipient `qa_pickups_bind` caller, so foreign recipient replacement registration
remains a concrete interoperability dependency, not an accepted capability.
