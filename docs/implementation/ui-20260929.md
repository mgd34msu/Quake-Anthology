# Native UI and HUD implementation, 2026-09-29

This packet continues B32. It adds a native seat controller, concrete game/mod/account menus and a common HUD. It does not complete B32, baseline source coverage, source-family HUD behavior or frontend integration. All files in this packet are new; earlier gameplay and ranking repairs remain untouched.

## Behavioral source and shared ownership

Read the TypeScript controller's stack, focus, input, fields, sliders, lists, binding capture and draw paths in `src/ui/common/controller.ts`, plus `src/contracts/ui.ts`. Read the complete addition-mod menu in `src/ui/mods/menu.ts`, generic library menu in `src/ui/library/menu.ts`, and account view/menu in `src/ui/settings/rankings.ts` and `ranking-account.ts`. Read the shared data/message contracts at the beginning of `src/ui/hud/index.ts`, and the settings/library match entrypoints for remaining scope. Paths in this paragraph are relative to `../quake-typescript`. No donor or original game source files were copied.

The controller owns only one seat's cursors, menu stack, field state, scroll state, held directions and input overlay token. Fonts, scene images, input, catalog, launch admission, inventory, combat and ranking services use their existing native owners. Row lists reuse retained storage and rebuild only after a query/selection/content change. Search uses the shared Unicode lowercase/whitespace helpers. Drawing uses the scene frame's scratch arena rather than another draw-command model.

Game launch uses authored start-command syntax, including the episode's introductory chain for its first start. It retains an existing launch seat roster. With no previous roster it admits the supplied real local seat/profile and input device; the actor ID stays zero until application publication assigns it. This menu intentionally chooses the selected preset's default providers. Individual mod editing copies the full active configuration instead, retaining independently selected foreign providers and instances.

Ranking account actions target an explicit admitted source slot. A seat ID or player name is never inferred as that slot. Credentials are copied only for the synchronous lifecycle operation and cleared afterward; close and slot replacement clear editable credentials. The NULL-provider unavailable behavior stays in the existing ranking service.

The HUD's `source_vitals` flag suppresses the common health/armor/ammo rendering when a selected source owns that display. It does not suppress shared inventory/messages. Source callbacks may inspect but must not mutate the application, HUD or controller during a draw. The provider and all returned spans survive that draw.

## Source review traces

- A clicked list row is copied by stable key before selection. Selection may rebuild views or change the menu. Activation reacquires the current menu/control and matches that key rather than using the old row pointer/index blindly.
- A field change borrows a temporary UTF-8 string only for its typed action. After the action, cursor state is reacquired only if the same menu remains active. Fields are keyed by menu plus control, so equal control IDs in different menus do not share a cursor.
- Opening the first menu pushes its borrowed input handler and explicitly sets UI focus; push alone preserves prior focus. Closing the final menu removes that token before dropping the menu. The input service commits retirement/focus restore even when a held source release reports failure, so close drops its stack entry and returns the cleanup error. Callback-active controller/menu/HUD destruction is rejected.
- Frame draws prevent menu/controller mutations while factory, source and owner-draw spans are in use. Factories and lifecycle hooks are read-only by contract; actions may open or close menus.
- HUD inventory definitions are copied into frame scratch, and borrowed labels are copied before subsequent inventory provider observations. Shared services supply the actor-generation and binding checks; this HUD does not retain their provider pointers.
- Refresh uses the root's shared exact empty-draft rebase. Reviewed its entire setter/ownership path and changed rebase diff: all choice arrays and provider option bytes are copied, every world/provider product ID is remapped by stable identity, missing products destroy the candidate without changing the old draft/output, and no preset defaults are inserted.

## Required integration and remaining baseline scope

The root owns CMake, the outer frontend, app service routing and source selection. It must add these new sources to its UI target; provide a shared white scene image, fonts, actual input seat/profile and localization/sound/clipboard/binding owners; construct/register/open the menus; and call UI tick/draw and per-seat HUD draw from the real frontend.

The mod menu currently requires an active launch snapshot and should be created after selecting a game. Mod Apply/Refresh compares the root configuration generation captured with its draft. A different menu's configuration change rejects stale Apply/Refresh; Cancel reloads current choices. Successful Apply captures the new generation. Catalog refresh preserves the old live launch snapshot independently of the new discovery catalog.

The ranking menu must receive/update the actual admitted source slot from root routing and run account actions on the app owner thread outside active service callbacks. The root must implement HUD read/source_draw adapters resolving `QA_ROLE_HUD` through its authoritative actor/seat/default selection. Inferring HUD ownership from Q1/Q2/Q3 family names would lose independent composition.

At the common controller packet freeze, remaining scope was: native source-family Q1/Q2/Q3 stat/layout drawing (including Q2 rerelease authored layout programs), wheels/carousel, POIs and directional indicators, source weapon-state presentation, full accessibility/color modes/themes/assets, legacy menu and Team Arena script/layout execution, save/restore library UI, comprehensive settings/input/lobby/services/rotation pages, complete match/vote/bot controls, inventory use/drop workflows, full mixed-role/loadout/monster/equipment selection UI, and persistence owners. These are baseline requirements, not cosmetic omissions. Generic command buttons or empty callback slots are not claimed as implementations of them.

## Native Q2 authored HUD source packet

`include/qa/hud_q2.h` and `src/ui/q2_layout.c` add direct native interpretation of authored layouts and inventory panels. Donor sources read completely: `src/ui/hud/q2-native.ts`, `src/ui/hud/q2-rerelease-layout.ts`, `src/app/bootstrap/q2-native-hud.ts`, and the protocol layout in `src/app/bootstrap/network/q2-layout.ts`; the rendering/localization consumers in `src/app/bootstrap/ui.ts` and `src/text/layout.ts` were read for source text scale and glyph behavior. The numeric prefix scan in `src/core/game-numeric.ts` and general `Tokenizer` in `src/core/common-parse.ts` supplied the token/operand semantics. These are donor-relative paths, not copied C source files.

The classic grammar includes all donor coordinate, picture, digit field, stat string, ordinary/alternate/centered text, client/CTF scoreboard and conditional commands. The rerelease grammar adds nested `if`/`ifgef`, lives, localized text variants and arguments, selected foreign item names, source player-name substitutions, source timing, dogtags, bounded authored tables, player-name stats, packed health bars and story text. Classic false-condition skipping preserves the donor's first-`endif` behavior; rerelease conditions consume disabled operands and reject unmatched conditionals. Story retains its unconditional source branch. Source status/overlay/inventory flags, classic 17-row and rerelease 19-row inventory scrolling, bindings, selection and cursor clocks are retained.

`qa_hud_q2_draw` is the production entry for the root-owned source HUD adapter; `qa_hud_q2_layout` supports separately authored status/overlay consumers. Both emit actual scene geometry/images through the shared scene/font arena, not a disconnected operation model. Wire stats/configstrings are source authority. Foreign arsenal icons, quantities and selected items are supplied as typed readouts instead of guessed from classnames. The root adapter must provide the actual selected HUD source protocol, stats, layout, inventory, configstrings, source pictures, bindings and localization/fonts and retain a table per seat. This registration is still integration work outside this packet.

The new shared `qa_tokenizer` in `include/qa/tokenizer.h` and `src/core/tokenizer.c` preserves general Unicode text, ASCII whitespace, line/block comments, quotes without escapes, unterminated-quote EOF behavior and the donor's 1023 UTF-16-unit token bound. Tokens borrow immutable source spans. A token-copy helper handles the donor's quoted CRLF normalization. The existing signed-byte `qa_common_parse` remains unchanged; its original COM_Parse semantics would discard unquoted Unicode. Native HUD parsing uses this shared tokenizer. Classic text emits source UTF-16 low-byte glyphs; rerelease classic-font mode emits UTF-8 byte XOR glyphs; selected fonts use shared Unicode glyph layout. Source pictures and fonts are retained by emitted frames. Table borders are clipped to visible coordinates before emission, avoiding nonprogressing float loops at large authored coordinates.

## Native per-seat wheel and carousel

`include/qa/hud_wheel.h` and `src/ui/wheel.c` implement the complete state transitions in donor `src/ui/hud/wheel.ts` and the wheel/carousel drawing block in `src/ui/hud/index.ts` (lines 291–317). `q1-wheel.ts` was read to establish source-slot/impulse/entity-byte-offset requirements; its line-oriented authored file decoder is not yet implemented in this packet.

The controller keeps only seat presentation state and stable item keys, observes actual source items on each decision/draw and calls a typed ordinary selection callback with canonical item identity and source ordinal. Items use retained ordering storage with stable source ties. Wheel opening resets cursor/analog/selection; pointer and right-stick movement clamp to source radius; source angular slices respect ownership; center dwell preserves the optional Q2 slot-zero behavior; close checks current ownership before selection. The carousel filters ownership, cycles past empty ammunition, begins from the actual active item and commits through the same ordinary selection callback after timeout or attack. Failed source selection returns an error and leaves the command output unpublished.

`qa_hud_wheel_prepare` supplies holster, attack consumption, lock deadline and time scale before source command encoding. This includes the selection-frame holster state after the carousel transitions closed/closing, matching the donor command boundary. Time arithmetic uses saturating native deadlines. Source observations cannot reenter mutation or destruction while callbacks are active. No second arsenal or device-input state is introduced. Shared scene/font drawing covers the actual wheel ring, cursor, selected labels/counts/warnings and carousel icons/counts.

Root integration remains required: register actual per-seat source-item/active/selection owners, send canonical `qa_input_event` with its authoritative seat, read detached wheel visibility (including fade/powerup mode) to suppress the common crosshair, invoke update and prepare before ordinary command admission, consume attack/holster/selection lock and permitted game time scale, and draw through the real HUD/frontend. Q1 rerelease `wwheel.txt` discovery/line-oriented parse and its exact guest entity byte offsets need a separate source adapter. Q2 source wheel configstrings likewise belong to its actual admitted source adapter. Generic placeholder selection or speculative class-name mapping is not provided. Root owns source registration/CMake.

Source-only checks read the complete new header/controller and each affected donor transition, checked actual input/font/scene signatures and callback publication order, and scanned whitespace. No runtime, compiler, parser, build or test was run. This packet is frozen for independent source review, not claimed as full B32 acceptance.
