# Native Q2 typed private state, 2026-09-30

This packet adds declaration-qualified KEX64 private objects to the actual original GAME/LEVEL/HOST owner sequence. `application_native_q2_continuation_portable` performs read-only artifact/declaration qualification before original save or restore callbacks. Capture, prepare and apply require the same complete inventory. Presence of RNG or connection offsets alone is insufficient. Stock declarations and classic/CRT private state remain unsupported; no existing stock artifact is claimed to have passed full-private admission.

The existing digest-qualified primary declaration must add `continuation.private.schema = 1`, `coverage = "kex-live-client-and-declared-globals"`, and `moduleCoverage = "original-complete"`. The artifact author must supply the audited complete mutable-root inventory and actual member offsets for that exact compiled artifact. The runtime does not infer C++ layouts, prove an arbitrary mod author's completeness assertion, or discover undeclared process allocations. This packet supplies the typed preservation mechanism and known original semantic requirements; authoring those concrete stock artifact declarations remains necessary.

Each `layouts` row has a unique name, `domain`, `byteLength`, and complete disjoint `fields`. Domains are `client`, `entity`, `image`, and `heap`. Exactly one complete client and entity layout must match the existing source world record extents. Image rows supply actual `rva` and positive record `count`; heap rows supply the original tagged allocator `tag`. Every byte, including original padding, requires one explicit field. Fields supply `name`, `offset`, positive `count`, and `storage`: fixed-width signed/unsigned integer, bool8, float32/64, pointer, or bytes with `pointerFree = true`. Finite floats and canonical bool representations are validated. Original `old_pmove` and command padding are preserved, including bytes used by source `memcmp`.

Pointer fields use original 64-bit representation and an explicit target: entity slot, source client slot, image RVA, or a named heap layout. `{ "kind": "image-or-heap", "layout": "..." }` qualifies source strings that can inhabit either the artifact or a genuine tagged object. `{ "kind": "image-record", "layout": "ctfgame.ghosts" }` qualifies whole records in the actual ghost array. Source addresses never enter the wire record. Image-only `reconstructed` spans require `producer = "original-init"`; apply retains the current isolated owner bytes produced by original initialization/reconstruction. Live entity, client and heap bytes cannot be replaced with initialization defaults.

Known original requirements include complete game and level roots, the exact 256-record CTF ghost array adjacent to the CTF header, original CTF election/timer/scoring fields, complete client preferences/UI/fog/old movement fields, and original source callback/registry pointers. Lag history must use the real TAG_GAME vec3 allocation and match `game.maxclients * game.max_lag_origins`. Menus retain the real TAG_LEVEL handle, entry arrays, admin settings, callback RVAs and original counts. Mover curve objects retain the original tagged float arrays and `savable_allocated_memory_t.count`. Complete entity rows cover the actual capacity, including unoccupied slots, preserving original slot-pointer semantics separately from canonical actor generations.

`qa_native_allocation_query` inspects the actual allocator ledger used by original TagMalloc in both direct and runner backends. Interior pointers retain their allocation base, size and tag. Client and entity roots must match the actual contiguous TAG_GAME allocations. Shared or cyclic heap objects receive one record identity, and incompatible views of the same allocation are rejected. Arbitrary CRT/new allocations, unqualified external pointers and conflicting object layouts fail explicitly. `qa_native_module_mutable_range` checks admitted immutable PE/ELF section metadata, requires writable non-executable image storage, and excludes overlapping non-mutable sections and ELF RELRO. Runtime memory access remains fallible; immutable metadata does not replace the actual write result.

The version 2 parent supplement includes a version 1 typed graph. Prepare validates exact input extent, artifact/declaration/launch identity, every root, pointer domain, original counts, complete field coverage, reachability, and agreement with saved source connection flags. Unreachable heap records are rejected. Limits are 128 layouts, 1024 fields per layout, 4096 objects, 65536 pointer references and 8 MiB of object bytes; the encoded graph also must fit the parent's 8 MiB limit.

Apply runs only after actual GAME, fresh isolated baseline SpawnEntities, LEVEL and HOST. It requires detached observers and primary claims. It resolves candidate table/client/image addresses and allocates all genuine tagged objects before resolving pointers, allowing cycles. All candidate identities, extents and relocations qualify before the first write. Heap records publish before source roots; no original callback executes during publication. The prepared token owns copied scalar bytes and portable references, and its declaration view borrows the retained candidate module owner. Once allocation or publication is attempted, a failed candidate must be discarded. Its native allocation ledger retains every new object until original source teardown/free-tags, including partial failure; freeing the token does not free live source allocations or lose teardown ownership. No rollback or post-failure resume is claimed.
