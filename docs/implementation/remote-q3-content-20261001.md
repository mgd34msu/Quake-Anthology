# Remote Q3 content source packet

This packet contains only `src/app/frontend/network_content_q3.c` and its header. It prepares actual selected Q3 content and defines the transaction boundary with the application private client factory. It is not a completed frontend network integration or runtime acceptance result. No configure, build, compiler, test, project binary, script, parser, generator, runtime or performance command ran for this packet.

The TypeScript source donors read were `content/catalog/index.ts`, `app/bootstrap/content.ts`, `app/bootstrap/network/remote-q3.ts`, `q3-client.ts`, `q3-client-content.ts`, `q3-client-downloads.ts`, `q3-downloads.ts`, `app/bootstrap/remote-seat-source.ts`, `remote-application.ts`, and `q3-client.ts` with its `qvm.ts` artifact and Init owner. The C source owners read were frontend network callbacks and source construction/lifetime, application guest Q3 roles/clients/exports/artifacts/save, launch metadata storage, catalog discovery/scoped mounts, VFS policy/clones/read receipts, and Q3 package/pure/reliable codecs.

The new content owner retains the genuine selected descriptor metadata, catalog, copied decoded gamestate, real mounted PK3 inventory, native package checksums and checksum feed, physical selected/base writable mount spelling, and real map acquisition. It selects `fs_game` through the actual Q3 base catalog and applies `sv_paks` order to its private view. It does not mutate the held foreign mixed source views or world. Every public operation qualifies the actual network connection epoch through the transport owner and the actual remote receiver through the application context owner.

Its states are catalog, prepared, published, and media ready. Package download admission consumes catalog inventory before preparation. Preparation applies server pure order and holds the real map resource. Each decoded gamestate needs a new owner, including same-map or same-feed replacements. The private application factory must publish a real descriptor with an independently owned clone of that prepared VFS and an advanced configuration generation with a new CGAME service lifetime at the same connection epoch. The content owner's metadata lease then keeps the actual published descriptor resources and view alive without granting execution lifetime.

Media completion requires the actual CGAME and UI producers' retained artifact resources, genuine acquisition recipes, successful Init predicates, and actual presentation media views. The consumer verifies immutable mount identity and server order, reads the real VFS journals, and marks native CGAME/UI role references with `qa_q3_pak_record_client_role`. That codec changes role flags without opening a canonical path. It produces CP only after media completion and rejects reliable commands that the current Q3 reliable owner would truncate. A map read or a canonical asset probe cannot satisfy the role predicate.

Required integration work remains:

- The application must implement a genuine private CGAME/UI descriptor factory and publication generation. Existing `qa_application_apply` mutates the full world and is not a private remote replacement transaction.
- The actual receiver export must expose its provider descriptor, so consumers can qualify the descriptor/receiver pair directly. The current public remote context exposes host/service identity only.
- The actual QVM/native artifact admission owner must retain the opened resource and acquisition recipe. Current `q3g_artifact` retains executable images/modules and qualified metadata but drops the original resource association. Successful Init completion must be distinct from the current VM `initialized` field, which also records an entered failing Init for shutdown obligations.
- The frontend must expose genuine media views for those admitted role lifetimes. Decoded gamestate must be readable during actual Init even while network signon remains unprimed. The current frontend gates its gamestate service with the primed boolean.
- The transport must attach the receiver/download owner, queue CP, and mark signon primed only after the real transaction completes. An application generation change produced by that exact transaction updates the retained connection binding rather than forcing fresh admission.
- Unknown `fs_game` needs real remote catalog discovery and selected/base writable directory creation. The donor creates those directories before rediscovery. Current C `qa_catalog_remote` maps installed discovered products only. A supplied fresh catalog is accepted without rebasing or replacing held foreign providers; no product or writable mount is fabricated here.
- Restore must import the saved immutable pool, private VFS order/policy/read journals, actual role artifacts and successful lifecycle receipts before reconstructing package references in that order. It must not call normal preparation, acquire a canonical module, replay Init, or silently reuse an unsaved reference order. This packet does not implement that enclosing restore transaction.

The owning root must register these new translation units after the source gate permits build work. Independent source review is requested; no source-only network pass is claimed.
