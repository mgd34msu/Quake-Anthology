# Native inline application-stack service

This packet implements the native inline application-stack service. Verification is source-only; no compiler, build, test, or executable was run.

The current `instrument_client.c:region_clean_call` services `NATIVE_WIRE_REGION` on DynamoRIO's clean-call stack. `service_memory_request` accepts checked memory operations and watch control there. It cannot execute arbitrary original C callbacks safely. `instance.c` and `observe.c` therefore reject native invocation while `region_depth` is nonzero. That guard must remain until an actual application-stack service exists.

The runner already has the required application-side command loop in `runner_child.c:child_request`. It accepts nested `INVOKE` and original-entry requests, preserves each connection depth, and executes them through the existing typed/libffi binding. Entry observation already redirects to an application closure. Inline observation needs a similar redirect while retaining the suspended instruction's context.

The service has two exported runner entries. A region service entry receives a fixed process-local packet containing region ID, phase, transport depth and the original processor state. It qualifies the packet against the instrumentation's actual top frame through a checked control marker, sends the region event through `child_request`, decodes the actual decision, and calls an exported resume marker. The marker never returns into source code. Instrumentation intercepts it, validates the top suspended frame, restores the original context with the selected replacement and destination, and redirects application execution.

DynamoRIO retains each suspended frame independently of the temporary clean-call stack. The frame owns a full `DR_MC_ALL` context, an aligned manual x87 state buffer, packet, separately retained region identity and cookie, and predecessor. Nested callbacks create nested frames. Admission is bounded to 64 frames and restricted to the actual owner thread. A failed identity, packet, transport, or restore check terminates the runner before source execution resumes.

The application helper stack begins below the original source stack and preserves the SysV x64 red zone, Windows x64 shadow space, and the appropriate entry alignment. The i386 helper receives its actual stack argument. Original source stack arguments, locals, and the red zone remain intact. The helper never uses an ordinary C return to resume the interrupted instruction.

Context restoration must preserve the complete valid SIMD state and manually saved x87 state. The wire's low 128-bit SIMD replacements modify only those declared fields; other retained context fields survive. DynamoRIO's [redirect API](https://dynamorio.org/dr__ir__utils_8h.html) requires `DR_MC_ALL` and describes the separate x87 restore requirement.

The existing instruction order remains committed-write flush and entry interception, region interception, then current-instruction write capture. Reading the final capture call falsified an initial suspected unexecuted-write defect: `observer_instruction_clean` does not capture the current instruction. After CONTINUE resume, a one-use bypass suppresses already-delivered entry interception and region events at the exact interrupted PC while allowing normal write capture and the original instruction to execute. For multiple region records at one PC it suppresses only records through the last delivered record. Nested callback writes flush before this bypass is consumed. SKIP_BODY still reaches the actual join event; frame exit preserves the declared original exit boundary.

`NATIVE_WIRE_REGION_APP` is appended to the existing wire opcode roster. Parent typed invocation and original-entry invocation require every suspended region to have that application-service qualification (`region_service_depth == region_depth`). Named export invocation remains guarded. A write callback nested inside the region still prohibits source reentry. Legacy `NATIVE_WIRE_REGION` remains accepted with its original restrictive admission.

Teardown, observer removal, checkpoint capture, and restore remain blocked while any source or callback frame is active. A terminal runner cannot resume these frames. Parent callback contexts remain owned until the original active command unwinds, matching the hard-cancellation packet's lifetime rules.

Changes are `hook_control.h`, `region_service.h`, `instrument_client.c`, `instrument_region.inc`, `instrument_observe.inc`, `runner_child.c`, `runner_host.c`, `instance.c`, `observe.c`, `internal.h`, and wire constants. No new compiled translation unit is necessary. The parent committed and released the preceding hard-cancellation packet before shared-path edits.

The source checks traced parent callback depths, the actual child direct instance (which does not retain declaration region rows), marker identity, original-entry bypass, nested frame ownership, resume-PC ordering, source body failure, module unload, and destruction. The new service delegates qualified typed calls to the existing real command loop rather than duplicating libffi invocation. The missing full stock private declarations, ordinary import failure cancellation, and broader cross-source guest reaction adapters remain separate baseline obligations.
