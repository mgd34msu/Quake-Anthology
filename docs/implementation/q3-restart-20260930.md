# Quake III round restart source baseline — 2026-09-30

The application owns `map_restart` as a round continuation. It retains the actual
selected GAME provider, mode generation, launch identity, encoded mode selection,
GAME console scope, and captured source command. A delayed restart records the
source time at request admission and its signed 32-bit deadline. Source time
comes from the real native session clock or the guest GAME engine clock.

The parser uses the selected source console's Q3 tokenizer and cvar registry.
An omitted delay means five seconds. Integer parsing follows the donor's
`nativeAtoi` saturation profile; multiplying the delay by 1000 and adding the
source time wraps to signed 32 bits. A nonzero delay schedules only when the
actual `g_doWarmup` floating value is zero. The drained application boundary
publishes the deadline through the authoritative GAME `CS_WARMUP` setter and
allows its source events to drain before the destructive round operation.

The round continuation is independent of the existing match map continuation.
Scoped config intents preserve a delayed restart. A queued actual match map
transition or ordinary travel cancels it. Clearing either a completed config
intent or a completed restart preserves the guard against restarting twice in
one actual outer application frame. The four settlement steps advance source
time within that frame; they do not manufacture another outer frame revision.

The native adapter calls `qa_q3_configstring_write` on the selected live
`qa_q3_game`. The GAME owner commits its authoritative slot value before the
existing source notification. The guest adapter calls
`application_q3_guest_round_configstring`, which uses the actual GAME gamestate
setter and reliable command producer. Scheduling does not infer source state
from the last application event.

The `QAMI` version 5 continuation contains a `QARS` version 1 round record. That
record saves source identity, command scope, request time, deadline, delay,
warmup policy at admission, announcement progress, and the completed restart
frame guard. Restore owns decoded selection bytes. Late reconnect checks the
actual mode/provider, command publication, source command, and GAME console
scope. It rejects a guard beyond the restored application's real outer frame.
The record contains no GAME, frontend, network, source callback, or operation
pointer.

At a due drained boundary, the continuation invokes the root-owned
`application_q3_round_restart` cut. Its `mutated` result distinguishes a retained
preflight failure from an operation that has crossed the actual destructive
boundary. A successful result must represent an actual mutation. Mutation clears
the pending request and retains the outer-frame guard even when a later stage
fails. The complete executor owns canonical actor retirement, source clocks,
authored map spawning, player roster/session carry, source GAME lifecycle,
client reconnection, settlement, and frontend/network publication.
The full executor and its GAME and network prerequisites are separate source
packets. This packet owns the pending continuation and their integration
interface.
