# Q3 guest application implementation, 2026-09-29

This packet implements application ownership for Q3 game, cgame, and UI artifacts. It is source work. No compiler, executable, test, parser, or benchmark was run.

## Source capability references

The donor is `../quake-typescript/src/compat/qvm/game.ts`, `cgame.ts`, `ui.ts`, and `abi.ts`. Game calls preserve INIT/SHUTDOWN, CLIENT_CONNECT/BEGIN/USERINFO/DISCONNECT/COMMAND/THINK, RUN_FRAME, CONSOLE_COMMAND, and BOTAI_START_FRAME command words. Cgame has initialization from a live client gamestate, console commands, drawing, queries, and modern input/event exports. UI has API validation, initialization, shutdown, input, refresh, menu, console, connection-screen, and CD-key query exports, with the legacy export limits retained.

The C implementation consumes existing `qa_qvm`, `qa_native_host`, `qa_q3_host`, Q3 network records and reliable history, console tokens, canonical actor registry, shared world, and session component services. Native Q3 uses the existing exact-target direct loader or an explicitly configured native runner. There is no CPU emulator in this application adapter.

## Files and behavior

- `guest_q3.c` constructs the provider owner without invoking guest INIT, exposes the source frame component, publishes map entity text, retires old map source callbacks/portal contributions, restarts game/cgame executors, and retains failed cleanup owners for retry.
- `guest_q3_roles.c` owns private executor/host lifetimes, retains a cache of immutable images/modules and qualified declarations for matching configured role artifacts, preserves primary resource references, and keeps provider aliases synchronized as cleanup consumes individual owners.
- `guest_q3_server.c` binds actual per-provider configstrings, userinfo, commands, reliable queues and bot callbacks. Existing outer admission/velocity/transport services retain their original contexts through wrappers. Configstrings larger than one reliable command use the source bcs0/bcs1/bcs2 continuation protocol.
- `guest_q3_clients.c` connects source client ordinals to live canonical actor IDs, invokes connect/begin/userinfo/disconnect/think/command exports, preserves map-travel firstTime, leases source input motion across the guest call, retains user commands, keeps a separate local gamestate for each source client, applies configstrings on reliable consumption, and copies caller-supplied snapshots into bounded history. Provider-owned actors must match their source ordinal; foreign actors use borrowed host bindings.
- `guest_q3_exports.c` admits companion roles, validates UI API versions, initializes cgame against the admitted client gamestate, and exposes source role exports and scoped console arguments. Game initialization remains in map publication.
- `q3_host.h`, `q3_host/host.c`, `cvars.c`, `common.c`, and `client_input.c` separate service registration lifetime from canonical actor ownership. Shared Q3 cvars retain engine lifetime and stable handles; private catcher and console registrations have their own role lifetime. `qa_console_contribute` keeps one provider-scoped command listing/dispatch entry while retaining independent registration contributions from its seats. Host teardown admission checks active service/world callbacks and live owned actor bindings.

## Integration contracts

The parent owns application provider switch routing, shared-service and native-instance factories, public frontend callbacks, source snapshot production, and console routing. The map worker owns canonical seat admission and travel consumers. Source INIT is after publication. Map retirement runs after carry capture and before old geometry replacement; portal contributions must close against the geometry that created them. Executors and host binding contexts survive until their canonical actors retire.

A game role can construct headless with real shared gameplay services. UI/cgame construction requires an installed frontend service factory. Local cgame consumes an actually connected source client. A standalone cgame needs real external client services. Snapshot ingestion copies supplied valid snapshots and does not synthesize an empty client session.
