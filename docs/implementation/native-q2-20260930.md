Write instrumentation covers application instructions outside the game image as well, including original library memory copies. REP operations expand to scalar iterations through drutil, and drmgr's original operand view identifies each actual store. A watched range captures its pre-store bytes; the next application instruction captures all post-store ranges before host repairs, then sends each written intersection, including unchanged stores. This boundary precedes entry redirection and inline-region callbacks. A separate pre-store capture follows any inline processor-state repair, so its effective address uses the repaired source state. It rejects same-instance application invocation from that boundary; only the application entry closure supports synchronous reentry.
