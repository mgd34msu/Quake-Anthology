# Native source entry cancellation, 2026-09-30

A rejected native entry callback now terminates its isolated runner before the libffi bridge can return into the original C caller. Previously the bridge reported failure but returned a default result, allowing the original enclosing source body to continue until the outer invoke returned. The original entry interception still runs on the runner application stack, and successful callbacks preserve the existing original-entry bypass and nested command order. This change executes no substitute source body.

The parent entry and region handlers send the actual rejection before poisoning the connection with the original callback error. Its next receive returns that retained error, rather than replacing it with a generic helper EOF. Existing declared-region failures already abort before another original instruction; explicit FAIL_INSTANCE now retains a concrete terminal error as well. The child entry bridge exits immediately on rejected/invalid responses or instance identity failure. It invokes no source Shutdown or exit handlers.

`qa_native_terminal` is a read-only query for an unusable poisoned runner. It does not classify a transient direct-backend error as terminal. `qa_native_terminal_retired` additionally requires the instance idle and every cached source slot's exact actor identity retired in the actual canonical registry. A live owned, borrowed or world actor blocks the qualification, as does a different actor namespace. A source without actor bindings can qualify without a registry. Cached slot identities are lifetime evidence only; they never stand in for an actual private-state read or snapshot.

Inactive entry/write observer removal on a terminal connection releases only parent-owned metadata. Callback, write and region lifetimes must drain first. The poisoned transport cannot admit further remote callbacks into those released contexts, and runner teardown kills/waits for the remaining process before releasing its owner. Healthy removal still requires actual remote control success and retains the binding on failure.

Native-Q2 application teardown first executes the existing combat and inventory detach operations. A live source primary that cannot provide its real snapshot still fails and retains its context. After actual canonical retirement removes the shared claims, the terminal host qualifier permits skipping impossible original Shutdown and consuming the runner. The host destructor independently enforces the same retired-slot qualification. Core destruction skips Shutdown only for an unusable runner, and retains its normal consume-after-admission contract; application/host owners remain responsible for their canonical ownership qualification. No old source values are synthesized, foreign actors are not forced to retire, and the initialized flag is cleared only after the terminal host gate succeeds.

Actual canonical retirement is an outer application producer prerequisite. Map retirement still cannot call ClientDisconnect in a dead source, and this packet does not invent that outer retirement transaction. Ordinary import/syscall callback failure policy and graceful retained-instance unwind remain separate work. The application-stack trampoline for inline region reentry is also separate: the region_depth guard remains intact.

Source evidence: `runner_child.c:child_observer_entry` and `child_request` establish the actual application-stack/libffi response path; `runner_host.c:handle_observer_entry`, `handle_region` and `runner_request` establish parent depth/error ownership. `protocol.c:native_wire_poison/native_wire_receive` retain the first transport failure. `observe.c` guards actual callback lifetimes. `instance.c:qa_native_destroy` consumes the admitted runner; `native_host/host.c` qualifies its real canonical slot owner. `guest_native_q2_combat.c:application_native_q2_combat_detach` and `guest_native_q2_inventory.c:application_native_q2_inventory_detach` preserve actual fallible snapshots for live actors and clear claims only after genuine retirement.

Verification is source-only: full response/error/observer/slot/host/application teardown call-chain inspection, whitespace checks and frozen SHA-256 inventory. No compiler, build, parser, project executable or test ran. This is a bounded entry-cancellation producer, not baseline completion or runtime verification.
