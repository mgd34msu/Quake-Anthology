# Native import and syscall cancellation

The runner's import and syscall closures execute in application code. Returning `false` after a rejected service let the generic libffi dispatcher supply a default return value and allowed original source code to resume. That behavior could continue an original damage, inventory, or lifecycle operation after the canonical owner had rejected it.

`child_import`, `child_describe_syscall`, and `child_syscall` now terminate the runner on failed callback identity, request construction/transport, response decoding, or result qualification. A successful callback keeps its actual typed return value and normal source ordering. Syscall description failure stops before the source varargs dispatch can read an unqualified argument list. Temporary response and value buffers are released and the previous child instance reference is restored before terminating a completed failed service.

Aggregate results require the exact libffi closure result extent both in the parent and child. Short results are rejected before source success: previously the child accepted them, then the generic final ABI encoder failed after the child service returned. The final ABI encoder also rejects pointer results exceeding the actual helper pointer width rather than truncating them.

The matching parent `handle_import`, `handle_describe`, and `handle_syscall` send the actual structured rejection, then poison the connection with that first callback error. A callback returning `false` without setting an error receives an explicit failure before serialization. The outer native command therefore reports that rejection rather than replacing it with a later end-of-stream error. No subsequent parent source callback may use a retained context.

Local TagMalloc/TagFree, formatted import, Q3 varargs, and final ABI encoding errors may occur before or after the remote child service. The generic failure latch now calls a private failure hook. It qualifies the actual child context, callback pointer, module identity, and active instance; ordinary direct owners return with their existing latch behavior. The child sends its actual first latched error through appended `NATIVE_WIRE_SOURCE_FAILURE`, whose parent handler validates the error envelope, replies with that rejection, and poisons the connection. The child then terminates before the original C caller resumes. A runner closure invoked on a foreign source thread terminates without accessing the owner-thread latch or transport. The global variadic source thunks still require the original engine's owning thread; this packet does not admit asynchronous module-created threads.

The preceding terminal qualification remains unchanged: active callbacks must drain, genuine shared primary detach may fail and retain the native owner, and remaining canonical slot references must actually retire or detach through their existing qualified ownership paths before host consumption. This packet does not fabricate snapshots, retire foreign actors, run Shutdown in an inaccessible terminal process, or free retained frontend/application contexts early.

Host-only checkpoint and restore control handlers were not changed, and do not call the new source failure hook. Their existing rejection and connection ownership semantics remain intact. An import invoked by an original WriteGame/WriteLevel callback is still a genuine source callback and cannot resume after failure. Named source export guards, region application-service admission, and write callback reentry restrictions remain unchanged.

Source verification traced closure dispatch, initial GetGameAPI/import instance attachment, exact typed aggregate copying and pointer representation, local allocation and varargs latches, Q3 description-before-varargs ordering, actual parent reply/poison/receive first-error flow, and retained terminal teardown. Scoped whitespace checks passed. No compiler, build, parser execution, test, or program run was performed.
