## Confirmed defects

1. **P1 — portable restore loses the location-chain head.** `src/gameplay/q3/map/checkpoint.c:322` commits `locations_linked` and returns from the no-reconnect branch without committing the already resolved and validated `location_head`. `save.c:626` uses this branch for real portable restore. An empty restored map therefore retains a null head despite saved linked locations, and TEAM location queries return absent immediately. Donor `content/q3/base/game/targets.ts:35–40` captures and restores both linked and head; native runtime `app/bootstrap/simulation/q3/runtime.ts:266` calls that restore. Minimal repair: assign `game->map->location_head = location_head` in the no-reconnect commit, as the reconnect branch already does.

2. **P1 — hitscan/contact effects have no physical source entities.** `weapons.c:64–77`, `:50`, `:180`, `:246`, `:331`, `:378` emit report events for bullet impacts, missile hits/misses, invulnerability impact, reflected lightning, shotgun blast and rail trail. `game.c:365` only forwards an event report. The real sink `src/app/application/events.c:338–364` copies reports to a queue; it constructs no source row. Donor `content/q3/base/game/weapon.ts:185–193`, `:211–212`, `:220–221`, `:242–249`, `:75` constructs real `pool.tempEntity` records, including source fields, lifetime, source allocation and link callbacks. A machinegun hit currently leaves no EV_BULLET_HIT_FLESH/WALL entity in the physical GAME table or network snapshot. Minimal repair: author real temporary source rows at the donor producer boundaries, with actual eventParm/otherEntityNum/clientNum/origin2/weapon/angles, retaining reports only as supplemental output. Shotgun must allocate/link its temporary before consuming the spread RNG seed; SDK `g_weapon.c:357–363` and donor shotgun begin callback establish that order.

3. **P1 — native timers depend on independently selected Q3 CHARACTER/EFFECTS.** `player.c:1160` skips the whole residual loop when both selections are foreign; `:1182`, `:1194` additionally gate ordinary overhealth/armor decay on Q3 CHARACTER. Real native `qa_q3_client_think_finish` calls this function at `:1579`. Donor native host `app/bootstrap/simulation/runtime.ts:2870` explicitly supplies `ordinaryDecay: true` independent of selection. `content/q3/team-arena/client-effects.ts:160–187` always advances source residual and performs that decay. Counterexample: native Q3 GAME with foreign CHARACTER/EFFECTS, maxHealth100, health101, armor101 and a 1000ms live interval; donor produces100/100/residual0, C produces101/101 and does not advance residual. Minimal repair: qualify genuine native clients separately and run native source timers/ordinary decay regardless of these provider gates; retain the existing nonnative selected-provider policy.

4. **P2 — accuracy uses canonical combat team instead of native session team.** `game.c:449` compares `ac.team != tc.team`. Native sessions are independent genuine source values (`client_begin.c:35–47` assigns them without rewriting canonical combat team). Donor `content/q3/base/game/weapon.ts:83–90`, `:172–174` derives native accuracy team from `client.sess.sessionTeam`; shared combat team is only the foreign fallback. In TEAM play, two native clients with RED sessions and differing canonical teams wrongly earn teammate accuracy in C; opposing sessions with equal canonical teams wrongly lose credit. SDK `g_weapon.c:746–770` calls genuine `OnSameTeam`. Minimal repair: use native session team for qualified native actors and preserve shared-team fallback for foreign actors.

5. **P2 — pre-movement gauntlet muzzle uses precise body rather than published source position.** `weapons.c:12–20` uses `q3_source_body_read`, while native `player.c:1710` runs the gauntlet before movement/BG conversion/currentOrigin scope. Donor `content/q3/base/game/weapon.ts:111–115` and SDK `g_weapon.c:782–804` use `entity.s.pos.base` for both muzzle functions. Real donor `client-think.ts:175` performs gauntlet before conversion at `:203–204`. Counterexample: previous BG publication has x0 from precise body x-0.9, view forward+x, and no currentOrigin scope; C snaps -0.9+14 to13, donor snaps source0+14 to14. Minimal repair: native weapon geometry reads the actual published source position, while foreign selected-Q3 actors retain their shared body contract. Do not alter canonical body to imitate publication.

6. **P2 — TEAM location ignores actual source currentOrigin scope.** `map/runtime.c:746`, `:761` read canonical body directly. Donor `content/q3/team-arena/team.ts:413–422` reads `entity.r.currentOrigin` and each location's actual currentOrigin for distance and PVS. Core already exposes real scoped currentOrigin via `source_effects.c:9`. A valid native query during a source origin scope can choose a location and PVS leaf using precise canonical coordinates instead of the active source coordinates. Minimal repair: use `q3_source_body_read` for client and location bodies, retaining the existing generation/callback checks. This contradicts the handoff's claimed currentOrigin support at source-resume line379.

7. **P2 — quad gauntlet authors the predictable ring rather than G_AddEvent.** `weapons.c:161` invokes `q3_player_event`, consuming predictable sequence/ring and subsequently pending temporary publication. Donor `content/q3/base/game/weapon.ts:241` invokes `pool.addEvent`; `entities.ts:218–237` writes externalEvent/Parm/Time and entity eventTime, without predictable sequence mutation. SDK `g_weapon.c:104–106` does the same. Minimal repair: invoke existing `q3_add_event`/genuine G_AddEvent producer for EV_POWERUP_QUAD.

8. **P2 — disconnect preserves the old PERS_TEAM.** `client_begin.c:403–418` changes connection/model/presence but leaves genuine source player persistent_team unchanged.
