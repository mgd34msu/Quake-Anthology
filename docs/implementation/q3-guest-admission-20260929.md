Combat-state observation parses original private fields, explicit namespaced team values, flag bits, mass representation and binary32 armor tiers.
- `guest_projection.c` reads and writes original private inventory words, preserves private packed bits, checks signed counter/capacity representation, and retains full actor generations. Binding callbacks hold the provider execution lease. A count write rechecks the actor/client record before writing a capacity word. `application_guest_player_state` reads actual source health, damageability, mass, team and armor; it is an observation API, not an implementation of original damage callbacks.
- `guest_bots.c` allocates through the existing host/session actor allocator, reserves configured human ordinals, respects the actual registered sv_maxclients value and located source limits, and retains pending bot admissions. Shared roster attachment receives actual source userinfo, public player view height/ping, source health and elapsed connection time. It does not call source Connect/Begin again or create a second world or inventory. Repeated FreeBotClient for an already-free slot is a no-op, as in the donor; it cannot retire a human client.
- `guest_admission.c` retains generation-specific drop/free work and the actual reason. ClientDisconnect is consumed once; canonical release waits source calls, world callbacks, host motion depth, and the input adapter's actor lease. A source callback error is preserved while independent idle cleanup continues. A borrowed actor is never released as if it belonged to this provider.
- `q3_host/input_lifetime.c` exposes the real admitted motion depth through `qa_q3_host_input_idle` and original player words through `qa_q3_host_source_player`; their public declarations are additive. Qualified gameplay observations preserve source tags rather than invoking presentation translation, which would reject irrelevant mod-private legacy powerups. The accepted native unload implementation is unchanged.
- Existing guest server, role, client, frame and console consumers use these bodies. Source game BOTAI_START_FRAME precedes RUN_FRAME. Pending admission/drain occurs at completed consumer boundaries rather than inside the generic source-call helper, so denial strings and command arguments retain their source ordering. Direct client disconnect consumes its callback before invocation, and source begin cannot publish a client that retired during the callback.

## Dependencies and unfinished behavior

The map owner has agreed on `application_players_guest_attach(app, provider, slot, actor, const qa_builtin_player_info *, error)` and its matching detach. These declarations are temporarily in the private projection header. Their production definitions, dynamic roster recognition/enumeration, default-player role routing and native auxiliary admission remain separate owner work. The new calls therefore do not establish working guest bots yet.

`qa_inventory_bind` accepts only an actor without an existing store, while human map admission already creates one. The adapter explicitly reports unsupported for that existing-store case. It needs canonical primary replacement preserving admitted native counts/groups and matching-context detach that snapshots actual source counts. A live source binding prevents projection-context destruction. `qa_inventory_close_items` was inspected: it only deactivates a contribution and does not snapshot source counts, so it is not a substitute for this ownership repair.

A borrowed character also needs a generation-matched host projection detach after source/input scopes drain. `qa_q3_host_actor_released` deliberately rejects a still-live actor. This packet reports unsupported for borrowed client retirement rather than destroying another provider's actor or claiming that detachment succeeded.

Public inventory catalog/capacity queries, builtin digest-qualified inventory/combat profiles, original damage/free/reaction/armor interception, native private gameplay projection, source pickup/drop/equipment projection, and complete source-frame movement completion remain open. The observation API must not be described as canonical combat binding. Native profiles are not interpreted as QVM entries or guessed private layouts.

The actual shared bot runtime still needs to reach the guest host's `options.bots`. Source snapshot production, human disconnect transport/frontend effects, complete save/restore/continuation ownership, root declarations and build-source registration remain integration dependencies. Retaining a drop reason is not proof that a real transport delivered it.

The bot owner confirmed that its current native population context is published after seats and exists only when configured native bots are present. A pointer getter cannot supply guest GAME_INIT/BOTLIB_SETUP earlier. The shared library lifetime must precede source initialization, while native population and guest dynamic navigation bindings join that same runtime later. This packet does not create another bot runtime or claim that lifecycle has landed.
