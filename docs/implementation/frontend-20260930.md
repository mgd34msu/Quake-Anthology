This bounded B32 contribution connects retained native presentation events to the existing scene/audio owners. B16–B21, B32, B34 and BASELINE remain open. No configure, compiler, test, executable, sanitizer or benchmark was run.

## Source behavior

Read the current frontend ownership/frame/publication paths, application event queues and provider content-context accessors, Q1/QC sound/lightstyle/particle producers, native Q2 sound/map producers, and the shared scene/audio implementations before writing these callers. Donor behavior came from `../quake-typescript/src/app/bootstrap/audio.ts`, `presentation-state.ts`, `rerelease-presentation.ts`, `rerelease-presentation/fog.ts`, `effects.ts`, `effects/particles.ts`, and `../quake-typescript/src/render/scene/particles/legacy.ts`. The C implementation uses the existing shared `qa_builtin_random`, particle state samplers, scene geometry and mixers. No donor file or original engine implementation was copied.

`map_events.c` retains actual provider content resources and per-seat lightstyles, fog and sky observations. Every provider resolves its content through captured application command provenance, then clones that VFS view. Shared immutable resource bytes remain owned by the VFS service. Equal filenames from independently selected providers do not select the geometry owner's assets by accident. CPU image diagnostics enumerate these event resource owners.

Native Q2 sound flag 1 admits a retained actor loop. Resource replacement replaces that actor/provider/family loop; STOP_SOUND removes its retained continuation and mixer loop. Live actor sounds follow canonical audio identities and authoritative body positions. Missing actors retire their retained loops. Q1/QC ambient sounds require looped PCM and enter each admitted seat mixer through the existing static-sound policy with source volume/attenuation quantization. Source event assets are retained independently of the transient queue, and logical sound work still runs when physical output is disabled.

Before presentation, the outer frame reads map events after network publication and scene synchronization. This occurs even when a window is minimized, so clearing the shared application queue cannot discard unconsumed persistent map updates. Q1 builtin LIGHT and Q2 MAP_LIGHTSTYLE patterns supply the shared world lightmap inputs at the source 10 Hz sample cadence. Q2 MAP_SKY loads all six authored faces, retaining per-seat overrides and substituting the existing missing image for absent source assets. MAP_FOG applies the source byte-color/sky-factor and signed-height conversion, prior-target transition semantics, and session clock. MAP_DYNAMIC_LIGHT retains canonical actor/provider identity, visibility, color, radius, direction, style modulation and authored distance fades. Those lights append to existing source lights instead of replacing them. Shadow-light projection/casters remain additional integration work.

`particle_events.c` supplies provider-private bounded source particle pools with shared geometry and palette owners. Q1 PARTICLES implements ordinary impacts and the source 1024-particle explosion branch. Q2 STEAM implements instantaneous and bounded sustained emitters at the source 100 ms cadence; FORCE_WALL emits the authored indexed particle line. Native and Q3 source-owned scene views submit these particles before the existing frame finish. Q1 particle continuation advances once after all local-seat submissions. The donor's 4096-particle pool and 32 sustained-steam limits are retained.

The network peer's frontend integration decorates source CGAME host client services before source lease publication, routes remote client commands to the peer reliable queue, supplies remote input sensitivity/weapon/server time, and skips the local server advance for a remote client. Source UI presentation and remote trap_Milliseconds use frontend real time; remote CGAME drawing uses the peer server clock. The root-owned application adapter gates CGAME before remote gamestate admission. The existing application caller remains the sole CGAME draw entry. Separate source world and HUD ownership preserves shared world/view/FOV rendering when native Q2 cgame supplies only DrawHUD.
