Documents copy authored data and compile curves once. Playback owns only timing,
event triggers and target selection. The donor's target-change initialization
and elapsed-second endpoint behavior remain observable and are retained. Native
float spline arithmetic and double cumulative distances replace JavaScript
temporary objects/rounding machinery; exact donor bitwise float output is not
claimed. Spline distance lookup uses binary search over retained distances.

Capture requests copy names, map names and script-origin text at admission. The
readback happens after presentation, once per pending batch; each request writes
that immutable frame. Actual source/client generations are checked through the
frontend context_active service. Tool callbacks hold a busy admission scope;
teardown/travel/console-detach/editing cannot free their owner during callbacks.
Native synchronous camera and disk operations finish before command-tail
dispatch, eliminating donor Promise/load-generation machinery without changing
the ordering contract.

HTTP copies all request data at submission. Callbacks occur only during ordinary
nonblocking pump; cancel marks current transfers and suppresses subsequent
consumer callbacks before returning. Reentrant submission/pump/destruction is
rejected. Completion copies CURL message data before removing the handle, since
the message storage is owned by libcurl. Failure messages omit URLs, credentials,
response bodies and raw request headers. Zero redirects is the default; enabled
redirects remain HTTP(S), with cross-host unrestricted authentication disabled.
Maximum response bytes apply to decoded streamed body bytes.

Filesystem publication reuses existing no-link writable-parent traversal and
secure sibling temporary creation. POSIX exclusivity publishes with linkat and
keeps all new versions mode0600. Windows publishes without REPLACE_EXISTING for
exclusive writes and creates private temporary files with a protected DACL for
the current creator SID. Both implementations retain atomic immutable-version
replacement and sync/write-through behavior. As before, a durability failure
can occur after publication; stale credential retries must reload state first.
