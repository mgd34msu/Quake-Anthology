# THE-870 event-ring admission

The frontend previously required half of the entire output ring to be free before advancing simulation. That was unrelated to the next event's actual size. It could stop every source with usable storage and no peers, or because a persistent owner still leased a retired page. The shared tick now performs ordinary cursor retirement and proceeds; the half-pool API and its four otherwise unused peer-pressure helpers are deleted together. Actual source/CLIENT construction readiness remains intact.

The actual tick, retirement, common ring and receipt functions passed GCC and Clang checks, with and without ASan/UBSan. With 3,976 of 8,192 bytes available, the old tick skipped its native delegate while the new tick advanced it. A lookup-retired persistent lease remained readable without blocking the tick. A stopped ACK did not become an ACK; the healthy peer continued, and the prefix retired only after a real ACK or terminal unsubscribe. Measured component ticks allocated and freed nothing. Outputs matched across all four variants.

These are component checks with controlled native readiness and ACK values, not a real-server protocol or frame-speed claim. Whole-source strict checks passed except the same four pre-existing Clang float-to-bool diagnostics in network.c before and after. Production, ASan and allocation-gate builds each passed the seven core suites.
