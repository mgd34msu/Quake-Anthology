# MIKE-02: Quake II initial facing

The shipped `qa-c` starts `base1` facing its selected authored `info_player_start` direction in classic Quake II and the 2023 rerelease. These checks used the actual executable, installed retail maps, genuine X11 keyboard input, and read-only debugger observations. They inspected both the control state and the camera axis submitted to the renderer. No player pose or game state was set through a debugger.

| Edition | Renderer | Authored yaw | Control yaw | Rendered yaw | Command + delta yaw | Continued frames | Exit |
|---|---|---:|---:|---:|---:|---:|---:|
| Classic | CPU | 135 | 135 | 135 | 135 | 60 | 0 |
| Classic | GL | 135 | 135 | 135 | 135 | 60 | 0 |
| 2023 rerelease | CPU | 135 | 135 | 135 | 135 | 120 | 0 |
| 2023 rerelease | GL | 135 | 135 | 135 | 135 | 120 | 0 |

All four sessions walked with normal movement, released the key, continued rendering, and quit through the ordinary console. The CPU checks and classic GL check used build `59c89987`; the rerelease GL check used the later `f504` build. This proves the reported initial facing on `base1`, without claiming every campaign spawn point.

The original behavior is `quake-2/game/p_client.c:PutClientInServer`: use the selected spawn yaw and represent the difference from the client command in `pmove.delta_angles`. The C path passes the selected body angles through `src/gameplay/q2/player/spawn.c`, handles the physical spawn in `src/app/application/map_players.c`, and initializes the actual command builder in `src/app/frontend/frame.c:control_binding`. Subsequent command frames apply the edition's delta angles. The live observations follow this whole path, including the actual renderer camera.

Machine-readable evidence is in [2026-10-05-q2-facing.json](2026-10-05-q2-facing.json). The exact raw runtime receipts remain in the private playtest archive; no game asset bytes are included here.
