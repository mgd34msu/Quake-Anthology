# THE-870 outgoing event-page custody

Recipient EVENTS documents now borrow immutable payloads from the one source event ring. Their row wrappers, dependency pointers and typed document use the existing recipient frame lease. Each document retains its selected source-page leases and the common string table until its final reference is destroyed. FRAME history does not extend EVENTS dependency retention. Persistent initial state retains the actual slot lease even after its source lookup is retired.

The same projection and constructor serve ordinary publication and initial READY. One inline control slot replaces the old zero-or-one heap array. The two payload-clone calls and outgoing wrapper callocs are removed. Independently decoded EVENTS keep their existing owning teardown and wire layout. There is no second event store, format, content fingerprint or publication barrier.

The bounded component proof uses actual projection/emission, ring, constructors/destructors, commit_queue/commit_free and pending-output disposal. Eight GCC/Clang plain/ASan+UBSan artifacts pass eleven custody scenarios; twenty strict TU checks pass. All eight transcripts match exactly: 54,833 payload bytes, or 55,049 bytes including test length prefixes. Cases include fourteen payload tags, five clock rules, recipient privacy, source/pool/string-owner destruction, persistent replacement/removal, delayed READY, two peers, FRAME versus EVENTS lifetime, five allocation failures and cold decode. Source/player admission, recipe I/O and error-forwarding boundaries are controlled fixtures; this is not a full server callback proof.

For that same projection, the old path requests 117 callocs / 14,745 bytes each time. The new path makes five existing lease-arena allocations: first use requests one 16,408-byte arena block; repeated use makes zero heap requests. The meter excludes lease acquisition, emission, encoding, transport and the rest of the frame. Wrapper used bytes are 11,784; shared source pages use 18,275. Logical document charge changes from 14,609 to 14,633 bytes because of non-wire custody fields; it is not unique resident memory. No frame-speedup or all-frame zero-allocation claim follows.
