# Detached launch metadata lifetime, 2026-09-29

Confirmed failure: the final snapshot execution reference called `close_instance`, then freed the launch instance descriptor resources and its owning draft. Application provider release can queue destruction when execution is active or cleanup fails. The retained provider's `launch` pointer and borrowed artifact/declaration/content views then referred to freed storage.

`qa_launch_instance_retain_metadata` now creates a detached descriptor lease. It copies one descriptor struct, including that view's snapshot-local roles, and retains existing immutable storage; it does not duplicate strings, content mounts or resources. A lease does not retain a snapshot or execution state. The final execution reference still calls `close_instance` once. Immutable storage is released after the last metadata lease and execution reference are gone.

The owner marks close as dispatched before entering the close callback. A closing guard prevents a synchronous provider cleanup from freeing the metadata owner when it releases its final lease inside that callback. The owner checks the remaining leases only after the callback returns. Deferred provider cleanup can instead release the lease later. Failure before preparation leaves no execution close callback; candidate reuse releases only its temporary metadata owner and keeps the reused execution owner's independent reference.

The coordinator owns the application consumers: acquire the lease before storing the provider's launch view, use the lease's view, and release it only after successful provider deconstruction. A preparation failure with an allocated provider must still transfer that provider for the manager's existing close path. Snapshot-local role routing continues to read snapshot views; a metadata lease does not change that authority.
