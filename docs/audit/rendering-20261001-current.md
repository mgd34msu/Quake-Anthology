## Confirmed defects

### R1. Sixteen-bit GL targets use a different color format from the donor

Severity medium. Original verdict CONFIRMED by source tracing; bounded correction independently verified by fresh complete source reads after the owner's leaf freeze.

`src/render/gl/passes.c:126`, `passes.c:469` and `passes.c:787` select `GL_RGB5` for alpha-free color buffers with at most 16 reported color bits. These are the ordinary gamma, object-opacity and prepared surface paths. `src/render/gl/save.c:615` repeats that selection for cold restoration and retained native transfer.

The TypeScript reference selects `0x8d62`, `GL_RGB565`, in `src/render/gl/output-gamma.ts:126` and `src/render/gl/object-opacity.ts:92`. An admitted RGB565 drawable therefore changes to five green bits when C routes it through these retained targets. Gamma, translucent objects and restoration can lose green precision.

The display accepts a requested 16-bit visual. Its minimum request is four bits per RGB component in `src/platform/display.c:198`, so this report does not claim that the constructor explicitly requests six green bits. The confirmed defect was the actual target format difference on an admitted RGB565 visual. NativeView corrected all four selections to `GL_RGB565` and froze the two-file leaf. This lane then reread `passes.c`, `save.c`, every other current GL implementation file, the private GL header and the public GL API in full. The native backup path remains RGBA8; alpha-bearing targets remain RGBA8 and higher alpha-free targets remain RGB8. Checked GL allocation/FBO failures remain possible; this verdict does not establish universal format admission or native image behavior.
