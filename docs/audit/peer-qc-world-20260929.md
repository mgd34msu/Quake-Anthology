## Confirmed findings

1. P1, reused qualified provider as authored entity owner. Qualification rejects ENTITIES against the provider's retained initial launch roles. A role-only candidate can reuse an initially qualified arsenal provider as its ENTITIES owner. The primary map spawn API then dispatches the declared logical initializer and succeeds without spawning authored entities. The map consumer now rejects the actual candidate qualified QC map owner before travel allocation or world retirement. The producer was asked to reject this through its authored map spawn API too. That producer repair remains subject to reread.
2. P1, failed-construction cleanup. Construction publishes the engine pointer and sets its nonzero actor capacity before allocating the binding table. Allocation failure returns false, and the provider immediately calls deconstruct. The unbind loop dereferences the absent table. The owner was asked to make optional binding-table cleanup safe without pretending a complete constructed engine exists. Superseding repair is awaiting reread.
3. P2, source input continuation. Input injection runs independently in both before and after calls, and the scope is popped at the end of each call. The donor opens the source field scope at before, retains source changes through the operation, and closes it at after. A before handler clearing `self.button0` without a declared canonical output leaves it cleared for an after handler in the donor; C reinjects the attacking canonical command and can fire again. Closing before also prevents nested movement-slice input from restoring its outer command scope. The owner was asked to retain matched scopes and drain failures/retirement explicitly. Superseding producer and control-consumer repairs remain pending.

Partial construction teardown traverses bindings only if the table exists. Successful before input retains a heap-owned scope and saved words until matching after; after does not reinject input. Nested same-actor scopes restore outer words only when closed. That separate root/Q2 consumer repair and peer remain integration obligations. This disposition is not complete QC declaration or interoperability acceptance.
